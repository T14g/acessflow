Arquitetura

Monólito modular. Um repositório, uma API Fastify organizada por módulos, uma página React e um worker Node. Não há microserviços, Redis, Kafka, Docker nem diretório real.

Página Vite → API :3000 → MySQL accessflow → outbox_events → Worker → Diretório simulado

A outbox é a tabela outbox_events. A mudança de negócio e o evento entram na mesma transação. Se o commit falha, não sobra evento. Se o processo cai depois do commit, a linha continua pending.

O worker reserva essas linhas com SELECT … FOR UPDATE SKIP LOCKED, chama o conector e grava concessão, membership e auditoria. Dois workers não pegam a mesma linha. Erro técnico volta a linha para pending, com espera que dobra até 15 minutos, no máximo 8 vezes. Recusa do diretório fictício não entra nessa retentativa.

Módulos da API

  • identity — pessoas fictícias, papéis e sessão
  • catalog — sistemas, perfis privilegiados e pares de segregação
  • access-requests — pedido, aprovação, recusa e revogação
  • access-guard — regras de risco; não chama o conector
  • provisioning — conector que escreve no diretório simulado
  • audit — trilha só de inclusão
  • outbox — gravação e consumo do evento

Os esquemas Zod ficam em packages/contracts. A página e a API importam o mesmo contrato de login.

Decisões

DecisãoPor quê
MySQL 8.3, sem PostgreSQL O PDF pedia PostgreSQL. Nesta máquina o que existe é o MySQL 8.3, e o Postgres ficou de fora de propósito. Ids são CHAR(36) gerados na aplicação. Payload do evento é coluna JSON. Tabelas InnoDB, sem ORM.
Usuário accessflow em localhost e em 127.0.0.1 O cliente Node se apresenta como localhost mesmo apontando para 127.0.0.1. Uma conta só em 127.0.0.1 era recusada. A senha fica no .env, que não entra no Git.
AccessGuard dentro da criação do pedido O contrato deixa a avaliação para o worker. A página do gestor precisa da nota mesmo com o worker parado, então a API avalia na mesma transação. O worker só repete a avaliação se a linha ainda não existir.
Worker em processo separado npm run dev sobe só API e Vite. npm run dev:worker sobe o consumidor. O flag ACCESSFLOW_EMBED_WORKER continua false para não manter três processos no notebook. O código do consumo é um só, em apps/api/src/modules/outbox/worker.ts.
Marcador recusa-simulada O PDF cortou antes de dizer como o conector falha. A justificativa com esse texto faz o diretório fictício recusar. Não é uma rota vulnerável: é o jeito explícito de demonstrar failed sem concessão.
Quatro papéis, sessão no servidor Colaborador, gestor, administrador e analista. O analista lê e não aprova. Ninguém aprova o próprio pedido. Um campo role enviado pelo browser é ignorado.
IA desligada A decisão de risco é determinística. Sem chave da OpenAI o fluxo inteiro continua válido.

As decisões registradas no repositório estão em docs/adr, da 0001 à 0007: monólito modular, só MySQL, outbox, AccessGuard determinístico, diretório simulado, sem vulnerabilidade ativa e papéis da aplicação.
